# Постановка задачи для согласования

## Предметная область

Проект относится к электронной коммерции и рассматривает работу продавца на маркетплейсе. Объект анализа — ежедневный спрос на отдельные товарные позиции продавца в одном регионе продаж.

## Прогнозируемый показатель

Целевой показатель `demand_qty` определяется как число оплаченных и не отменённых единиц конкретного SKU, заказанных за календарный день.

Прогноз строится ежедневно на следующие 7 календарных дней отдельно для каждой из 30 выбранных товарных позиций. В первую версию включаются позиции, для которых сформирована история не менее 365 дней. Если товар отсутствовал на складе, нулевые продажи не интерпретируются автоматически как нулевой спрос: периоды отсутствия маркируются и анализируются отдельно.

## Практическая задача

Результат прогноза используется для планирования пополнения запасов. Система должна помочь пользователю:

- оценить ожидаемый объём спроса по SKU на ближайшую неделю;
- заранее обнаружить риск дефицита при текущем остатке;
- определить приоритет товарных позиций для пополнения;
- оценить, как календарь, цена, скидка, промоактивность и погода связаны со спросом;
- видеть не только точечный прогноз, но и диапазон его неопределённости.

Предварительная управленческая метрика — ожидаемый дефицит:

`stockout_risk = upper_forecast_demand_7d > available_stock + planned_receipts`.


## Пользователь результата

Основной пользователь — менеджер продавца по запасам и ассортименту. Он ежедневно решает, какие товары и в каком объёме пополнять, а также какие позиции требуют внимания из-за вероятного дефицита или необычного изменения спроса.

## Источники данных

Основной источник — синтетический инкрементальный поток заказов и состояний ассортимента, имитирующий ежедневную выгрузку кабинета продавца. Внешние источники — производственный календарь isDayOff и исторические/прогнозные погодные данные Open-Meteo. Подробное назначение, формат, способ обновления и ограничения каждого источника описаны в [02_data_sources.md](02_data_sources.md).

## Временная схема и доступность факторов

Момент построения прогноза — 06:00 по московскому времени после завершения загрузки данных за предыдущий день. В признаки попадают только сведения, доступные к этому моменту:

- фактический спрос, цены, скидки и остатки — не позднее предыдущего календарного дня;
- календарные признаки — заранее на весь горизонт;
- погодные признаки будущих дней — только из прогноза погоды, доступного на момент запуска;
- фактическая погода будущего периода не используется при обучении так, чтобы создавать утечку данных.

## Критерии успешности

1. Все загрузки инкрементальны и идемпотентны, а каждый запуск записан в журнал.
2. Качество прогноза оценивается с сохранением временного порядка данных.
3. Сезонная наивная модель сравнивается минимум с двумя дополнительными моделями по MAE и WAPE. Для разреженных рядов дополнительно рассматривается RMSSE.
4. Итоговый прогноз сопровождается интервалом неопределённости.
5. Дашборд показывает факт, прогноз, точность и риск дефицита и отвечает на конкретные вопросы пользователя.
6. Все преобразования и признаки обосновываются результатами разведочного анализа.
