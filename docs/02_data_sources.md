# Источники данных и ограничения

## 1 Синтетический поток заказов и ассортимента

**Роль:** основной источник целевого показателя и управляемых факторов.

**Способ получения:** локальный генератор ежедневно создаёт новую порцию событий в формате JSON Lines или Parquet. Повторный запуск с теми же датой и seed формирует те же записи, что позволяет проверить идемпотентность.

**Минимальный состав полей:**

- `order_id`, `order_item_id`, `event_time`;
- `sku_id`, `category_id`, `quantity`;
- `unit_price`, `discount_pct`, `promo_flag`;
- `order_status`, `payment_status`;
- `available_stock`, `planned_receipts`;
- `warehouse_id`, `sales_region`.

**Исторический объём:** не менее двух полных лет ежедневных наблюдений для 30 SKU. Генератор должен воспроизводить недельную и годовую сезонность, промоэффекты, изменение цены, редкие аномалии и периоды отсутствия товара.

**Обновление:** ежедневно, только за ещё не загруженные даты. Ключ дедупликации — сочетание `order_id` и `order_item_id`; для снимков остатков — `snapshot_date`, `warehouse_id`, `sku_id`.

**Ограничение:** синтетический поток пригоден для демонстрации архитектуры, статистических методов и воспроизводимости, но не доказывает коммерческую точность на данных реального продавца. Это ограничение должно быть явно отражено в курсовой работе.

## 2 Производственный календарь isDayOff

**Роль:** внешний календарный фактор.

**Источник:** [isDayOff API](https://www.isdayoff.ru/).

**Данные:** признак рабочего/нерабочего дня, праздничные и перенесённые дни для России.

**Формат и способ получения:** HTTP API, текстовый или JSON-ответ в зависимости от метода запроса.

**Обновление:** календарь загружается по годам; при повторном запуске обновляется только изменившийся или отсутствующий период.

**Доступность на момент прогноза:** значения известны заранее, поэтому могут использоваться на всём семидневном горизонте без утечки.

## 3 Open-Meteo

**Роль:** внешний погодный фактор для региона продаж.

**Источники:** [Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api) и [Forecast API](https://open-meteo.com/en/docs).

**Данные:** средняя, минимальная и максимальная температура, сумма осадков и код погодных условий по дням.

**Формат и способ получения:** REST API, JSON; запрос по координатам региона и диапазону дат.

**Обновление:** исторические данные догружаются за завершившиеся дни, прогноз — при каждом ежедневном запуске.

**Доступность на момент прогноза:** для будущих дат используется только тот прогноз погоды, который был доступен во время расчёта спроса. Фактическая погода будущего периода в признаки не подставляется.

**Ограничение:** влияние погоды зависит от товарной категории. Погодные признаки включаются в итоговую модель только после анализа связи и проверки качества на временной валидации.

## Разнородность источников

Основной поток формируется как событийные файлы с заказами и снимками остатков. Внешние признаки поступают по HTTP API и имеют календарную и метеорологическую семантику. Источники различаются способом получения, форматом, частотой обновления и назначением, поэтому удовлетворяют требованию разнородности.

## Контроль качества и журнал загрузок

Для каждого запуска сохраняются источник, время начала и окончания, запрошенный период, число полученных и записанных строк, число отброшенных дублей, статус и текст ошибки. Минимальные проверки:

- уникальность ключей событий;
- отсутствие отрицательного количества и остатка;
- допустимые статусы заказа и оплаты;
- непрерывность календарных дат;
- соответствие единиц измерения;
- доля пропусков и задержка поступления;
- отсутствие данных позже момента построения прогноза.

## Запасной вариант реальных данных

Если преподаватель потребует реальный исторический набор, синтетический поток можно дополнить [Brazilian E-Commerce Public Dataset by Olist](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce). Он содержит обезличенные сведения о заказах, товарах, продавцах и датах, но ограничен периодом 2016–2018 годов и не обновляется регулярно. Поэтому он подходит для проверки схемы и первоначального анализа, но не заменяет инкрементальный поток системы.
